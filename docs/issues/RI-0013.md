### Summary
Workspace create/provision and invite/join lifecycle. Owners cannot create workspaces and teammates cannot be invited or join from our console; only Octo's portal offers these. This slice adds the four creation flows' backend and switcher entry points.

## PDD
Switcher footer: 'New workspace…' (owner) and 'Invite teammate…' (admin+). New workspace lands on an empty-state Today with three actions. Invite shows email+role with plain-language capability hints and a pending row in Team. Teammate signs in with the invited Google address and lands in that workspace; an uninvited signed-in user gets an explicit join screen, never an empty dashboard.

## SDD
POST /app-api/workspaces (owner; requires account-scoped OCTO_ACCOUNT_KEY because Octo forbids workspace keys minting workspaces; disabled-with-explanation until supplied) then idempotent ri_console DDL imported from bootstrap-octo.mjs with workspace_meta marker; POST /app-api/workspaces/:id/invites (admin+) via Octo members; own-Google callback resolves member -> pending invite activation -> deny; provisioning retry route for partial failures.

## Eval / Completion Oracle
Hold-out MR5 (create twice/re-provision idempotent) green when account key configured, else SKIP with reason; U4 second browser joins invited workspace and switcher lists only memberships; non-member gets join screen. Gates pass on candidate.
