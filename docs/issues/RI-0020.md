### Summary
Dual-ledger architecture (Epistemic Graph + Append-Only Operational Ledger in `ri_console.ledger_event`) paired with Arize Phoenix OpenTelemetry/OpenInference tracing, linked end-to-end by a shared `trace_id` and `run_id`.

## PDD
Business truth and audit history live permanently inside the single Octo workspace (so users and agents can always verify *what* changed, *who* decided it, and *what evidence* supports a claim), while high-volume LLM/tool/retrieval telemetry streams to Arize Phoenix for debugging, cost tracking, and evals. Owners/admins in Deep altitude can jump from any agent run, approval, or claim directly to its Phoenix trace without polluting product tables with raw prompt dumps or leaking secrets/PII into observability spans.

## SDD
1. **Store Separation:**
   - **Epistemic Ledger (Octo Graph):** `Entity`, `Claim`, `Evidence`, `Belief` — sourced facts about people, companies, and events; claims carry `workspace_id`, `CITES → Evidence`, `validFrom`, and `supersededAt` (append/supersede, never overwrite).
   - **Operational Ledger (`ri_console.ledger_event`, append-only SQL):** Immutable audit log of every state transition — connector ingestion, routing, approval created/decided (`stop | re_plan | snooze`), plan locked, external action sent, membership/role change. Columns: `id`, `workspace_id`, `project_id`, `principal_id`, `agent_id`, `run_id`, `trace_id`, `event_type`, `entity_kind`, `entity_id`, `payload JSONB`, `created_at`. Never `UPDATE`/`DELETE`.
   - **Phoenix Traces (Arize Phoenix via OTLP/HTTP):** Separate Phoenix deployment (self-hosted `:6006` or Phoenix Cloud). One Phoenix project per environment (`ri-prod`, `ri-dev`, `ri-evals`), never per workspace; 14–30 day retention.
2. **Instrumentation (`app/server/telemetry.ts`):**
   - Initialize `@opentelemetry/sdk-node` at adapter startup targeting `PHOENIX_COLLECTOR_ENDPOINT` (graceful no-op when unset so local dev and CI never fail).
   - Emit OpenInference span kinds (`agent`, `llm`, `tool`, `retriever`, `chain`) so Phoenix renders waterfalls, token/cost counts, and evals natively.
   - Stamp every root span with tenant/context attributes: `ri.workspace_id`, `ri.project_id`, `ri.principal_id`, `ri.agent_id`, `ri.run_id`, `ri.cadence` (`daily | pre_event | signal | interactive`).
3. **Trace Bridge (`trace_id`):**
   - Every agent run, connector sync, or chat turn records its 32-hex OTel `trace_id` on `ri_console.agent_run`, `ri_console.ledger_event`, and any `Claim` provenance written to the Epistemic Ledger.
   - Deep altitude surfaces a deep link (`${PHOENIX_UI_URL}/projects/.../traces/${trace_id}`) for owners/admins when `PHOENIX_UI_URL` is configured.
4. **Privacy & Secret Hygiene:**
   - Scrub bearer tokens, cookies, API keys, and raw private email bodies before OTLP export; emit IDs, counts, and redacted summaries by default (dev-only `PHOENIX_CAPTURE_CONTENT=true` opt-in for full prompt capture).

## Eval / Completion Oracle
Running an agent turn or approval decision writes an append-only row to `ri_console.ledger_event` carrying a non-empty `trace_id`; when `PHOENIX_COLLECTOR_ENDPOINT` is set, matching OpenInference spans arrive in Phoenix tagged with `ri.workspace_id` and `ri.run_id` with zero leaked tokens/secrets; when unset, the server boots and passes all tests cleanly with zero telemetry errors.
