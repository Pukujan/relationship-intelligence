### Summary
The Profile page in production answered "Profile didn't load" with a raw zod issue list because two connector-imported file rows and one note row lacked the fields the console contract requires. Strict whole-payload validation turned a data-quality problem into a full page outage: the profile view loads files alongside the profile, so one malformed file row took down the person's own profile.

## PDD
A person opens their Profile and sees who they are (name, role, team, goals, preferences), their knowledge (files, notes), and their recaps. A file imported from a connector, or an older note, must never make that page unreadable; at worst the offending row is hidden and the rest of the page renders.

## SDD
app/server/profile.ts serves /app-api/files and /app-api/notes; console/src/data/profileTypes.ts validates the payload with zod before render. The fix adds app/server/knowledgeShape.ts (completeFileDoc, completeNoteDoc), mirroring the existing completeAgentDoc pattern, applied on read in the profile routes and the world read, followed by per-row safeParse: an unrenderable row is dropped and reported in `dropped` rather than failing the response. Malformed file_link rows are skipped without taking their file down. The three affected production rows were repaired in place with a merge-only `doc || {...}::jsonb`.

## Eval / Completion Oracle
Every live ri_console.file_doc and ri_console.note row passes ProfileFileSchema/NoteSchema. A deliberately unrenderable row returns HTTP 200 with the good rows intact and a `dropped` entry. Tests, typecheck, and lint pass on the exact candidate.

### Honest Caveat
