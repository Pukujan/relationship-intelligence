### Summary
The copilot is a modal single-exchange dialog, so ongoing research blocks the graph it reasons over, parallel questions are impossible, and thread state dies on reload. This slice replaces the modal with persistent, scope-pinned conversations rendered as tabs, typed visual parts, real streaming, and a context panel; a companion dock projecting the signal layer follows as RI-0011. The governing rule from the owner: windows are views, not brains — one session store, one approval queue, one telemetry stream.

## PDD
A person opens tabs the way they open browser tabs: one per research thread, each pinned to a scope (workspace, project, person, mission) with visible chips stating what the tab can see. Threads persist in Octo and resume across reloads and devices. Messages are ordered parts — text, table, KPI delta, sparkline, graph snippet, timeline, proposal, approval, artifact — rendered by real components, streamed as produced. Agents appear as participants inside a thread, never as separate windows. HTML artifacts render sandboxed (no scripts, no same-origin) with source chips and unverified flags. ⌘K opens or focuses a tab instead of a modal exchange. Proposal and approval parts approve inline through the same decision path as the inbox, which remains the canonical queue.

## SDD
Conversations and messages live in `ri_console.conversation` / `ri_console.message` (principal-private by default, promotable like all work), parts stored as validated JSONB. The copilot server gains `POST /api/session/:id/message` returning SSE; it builds a scoped digest plus hybrid RAG matches, routes through the existing provider pool (explicit choice or policy, cooldowns and failover unchanged), validates each part server-side before storage, and persists the message. The client renders parts with existing components; artifacts render in `iframe srcdoc` with `sandbox` and CSP `default-src 'none'; style-src 'unsafe-inline'; img-src data: https:`, scripts and event handlers stripped server-side. The source seam keeps guest and owner on one contract. Telemetry adds per-part evals (groundedness, schema validity, sandbox safety) to the existing span/eval export. Session hygiene: pinned active tab, auto-archive after 14 idle days with restore, warn above 8 open tabs.

## Eval / Completion Oracle
Two parallel tabs with different pinned scopes never leak each other's claims (property test). Reload and a second signed-in device resume the same tabs. Inline approve and inbox approve produce identical state (parity test). An artifact containing `<script>` and `onerror` executes nothing (escape test). SSE parts arrive progressively through the dev proxy (no buffering). Per-part eval spans are readable via `otel/read/span_annotations`. Guest mode keeps the same contract on seed data, labelled demo. Required gates pass on the exact candidate.
