### Summary
Collection is planned to run entirely inside TinyFish cloud browser profiles, and no collector has ever completed a run against a saved session. The project's only profile reports no signed-in sites, and the CLI-generated setup link returned a dashboard 404. This proposes running collection in a local daemon that drives a persistent browser profile on each teammate's own machine, with Tauri as a later packaging layer, and records the schema change that follows.

## PDD
A teammate installs a small collector service on their laptop, signs into LinkedIn, X, Luma, or Gmail once in a normal browser session, and the session persists across restarts because it runs from their own network address and browser profile. They pair that machine to their account, see its status on the connections screen, and start collection plans. When their laptop is asleep or the daemon is stopped, the plan pauses with a reason that names the device rather than reporting a confusing session failure.

## SDD
A local daemon owns a dedicated browser profile directory and drives Playwright against it. It exposes a narrow localhost contract to the existing React application and reports device presence, source status, and run progress. `source_connection` gains `device_id`, `device_label`, `pairing_status`, and `last_seen_at`; it still stores no cookies, passwords, one-time codes, or raw browser state. Session states keep their existing values and gain a device-presence reason so that an expired source session is distinguishable from an offline device. Octo remains canonical for evidence and facts. Tauri is a packaging shell that spawns the daemon as a sidecar; it is not a browser automation host, because its system webview cannot be driven by Playwright.

## Eval / Completion Oracle
A persistent Playwright profile signs into one source, survives a full daemon restart, and completes one read-only LinkedIn profile fetch without a re-authentication challenge. Two paired devices cannot read or execute each other's source connections. A stopped daemon marks its connection as device-offline rather than expired, and resuming the daemon restores the connection without a new sign-in. An expired source session stops only that source. No cookie, password, one-time code, or raw browser state appears in application records or logs.

### Risk Introduced by a Proposed Change
A local daemon moves operational burden onto teammates: an uninstalled or stopped daemon is a stalled collector. A dedicated local browser profile also concentrates a person's live sessions in one directory on their machine, which requires that directory to be permission-restricted and excluded from any backup or sync target.
