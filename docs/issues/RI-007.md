### Summary
The first plan assumed CSV imports and one operator. The owner has selected authenticated source exploration and teammate access instead. This replaces the earlier bootstrap/intake scope with individual Google accounts, per-person TinyFish/source sessions, and durable collection plans before the application shell is implemented.

## PDD
A teammate signs into the shared application with Google, sees only workspaces they belong to, and connects their own TinyFish and source accounts. They create a durable plan for LinkedIn profile/activity/organization exploration, Luma events, X, and optionally private Gmail/calendar windows. The first slice delivers authentication, source ownership, and plan/run configuration; the following collector slice performs scrolling, expansion, pagination, evidence capture, and resumable task execution.

## SDD
Octo principals and memberships authorize application/workspace access. Application records map each source connection to one principal, provider profile ID, and source account. No source session or provider credential is shared between teammates. Private observations stay in personal workspaces until approved for the shared workspace. Octo Files/RAG/ledger remain canonical for source material and facts; workspace Postgres stores connections, plans, runs, task checkpoints, and review state. ABA produces React/Vite/TypeScript; a thin server adapter is required for authenticated session and provider credential handling.

## Eval / Completion Oracle
Two test principals can authenticate independently. Each can register a source connection and collection plan, but cannot read or execute the other's by guessing IDs. Revoked membership fails even with a cached app session. Runs persist task state and resume after interruption without duplicate observations. Session expiry stops only the affected source. The first collector acceptance uses a small real saved-session fixture and exercises scrolling, section expansion, source evidence, and resume—not just synthetic screenshots.
